# Canonical AIA income integration

PR #12 reads `AIA優悅年金_官方保證收入率` from the existing AVA - EverBliss workbook. The reader checks the 144 rows including ages 40–49 with no total estimates, and publishes the 104 combinations ages 50–75. Numeric Sheet cells are percentage points (6.600 means 0.066); nonguaranteed is computed as total minus guaranteed. Interpolated total rates are checked against the stated proposal anchors; exact guaranteed rates are read from each row. `getIncomeRates`, the public dataset and the Admin income list all use this canonical reader. The 2026-10-28 read-only test snapshot is also the basis of the packaged fallback; it is not a replacement for updating the Sheet. An untagged older last-known-good dataset is rejected rather than silently overriding this canonical fallback.

Canonical income is included in the publication hash. Public published-data actions fail if the version and fingerprint do not match. A new code deployment therefore requires the owner to verify the canonical Sheet, review the live script and perform the existing controlled dataset verification/publication process so that metadata contains the new fingerprint. This repository change did not deploy GAS, publish data, or verify live Script Properties. Customers may see the local fallback while the live endpoint is unavailable or unpublished.

Income Admin writes remain blocked: the existing form submits independent field changes, which cannot safely preserve official guaranteed values, atomically recalculate nonguaranteed from the total, and preserve row/source provenance under the existing transaction model. Other Admin domains retain existing authorization, version-conflict and rollback paths. The UI is unchanged; an attempted income publish returns `INCOME_CANONICAL_SHEET_EDIT_REQUIRED`.

The HKMC read endpoint remains reference-only, HK$1,000,000 single-premium basis, no scaling or inferred surrender/death values. The read-only Sheet snapshot has 52 rows. Product and policy terms, live endpoint and real-device behaviour require separate verification. Prior AIA image redistribution permission and mounted-host re-entry limitations remain unresolved.
